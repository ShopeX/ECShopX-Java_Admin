# Plan：ECX-10022 管理后台语言设置页面

> 来源：TB ECX-10022 / 父任务 ECX-9889 / PRD `ECX-9889-language-settings`  
> 仓库：`ecshopx-admin`（当前基线 `master-standard-java`）  
> 原型：`ecshopx_prd/prototypes/ECX-9889-language-settings/pages/admin-language-settings.html`  
> 依赖：ECX-10021（跨端配置能力，已完成）  
> 设计稿：**不依赖 Figma**，以 HTML 原型 + annotations 为准

## 目标

在「设置 > 系统配置」下交付语言设置页：固定四种语言的查看/启停/默认语言、保存校验、成功反馈、未保存离开确认；并让后台语言入口按已保存配置生效（F-001～F-006，以及本端 F-007）。

## 现状结论

- 系统配置路由已有「通用设置」等条目（`src/router/routes/modules/setting.js`），**尚无「语言设置」菜单/页面**。
- 已有全局语言切换组件 `src/components/sp-language`，当前硬编码四种语言，**未读取站点已保存配置**。
- 后端只读配置接口已由 ECX-10021 提供（vshop 侧已接 `GET /setting/language`）；admin 需确认管理端读写接口路径与字段（与 Apifox/后端对齐）。

## 实现步骤

1. **菜单与路由（F-001）**  
   - 在系统配置分组、「通用设置」之后增加「语言设置」路由与菜单。  
   - 复用现有系统配置权限模型（不新增权限），入口随分组收起/展开。  
   - verify：展开系统配置可见入口；点击后选中态正确。

2. **语言设置页（F-002 / F-003 / F-004）**  
   - 对照原型实现列表：中文 `zh-CN`、English `en-US`、العربية `ar`、中文繁体 `zh-TW`（顺序固定，不可删）。  
   - 行内：启用开关、默认语言单选、作用范围文案；顶部摘要（已启用数 + 当前默认）；底部影响提示。  
   - 无配置时初始态：仅中文开启且为默认。  
   - 规则：关最后一个语言立即阻止并提示「至少保持一种语言开启」；关闭当前默认语言时清空默认并提示重选（不自动指定）。  
   - 开关开启态用主色强调、关闭态弱化（对齐原型，Tailwind 优先）。  
   - verify：切换即时更新摘要/未保存态；关默认语言不自动替选。

3. **保存与校验（F-005）**  
   - 无变更时保存按钮禁用/弱化；有变更且校验通过可保存。  
   - 校验文案按 PRD：全关 / 无默认 / 默认已关。  
   - 成功提示「语言设置已保存」，清除未保存标记。  
   - verify：非法配置无法落库；成功后读回一致。

4. **未保存离开（F-006）**  
   - 文案：「当前有未保存的语言设置，是否放弃变更？」  
   - 继续编辑保留；放弃变更恢复最近保存并允许离开。  
   - 覆盖菜单跳转；浏览器刷新/关闭按宿主能力提示。  
   - verify：无变更离开不弹窗；有变更拦截且不重复弹窗。

5. **后台语言入口生效（本端 F-007）**  
   - `SpLanguage`（及启动默认语言）改为只展示已启用语言；无个人偏好时用站点默认语言。  
   - 保存成功后当即刷新入口列表。  
   - verify：关闭语言后入口消失；个人已选偏好不被配置保存直接改写（已关闭则下次进入回落默认）。

## 风险与待确认

- 管理端读写 API 的具体 path / 字段名需与 ECX-10021 后端契约对齐（vshop 已用 `defaultLanguage` + `enabledLanguages`）。  
- 菜单权限码是否复用 `publicsetting` 还是新增 `languagesetting`：PRD 写「不新增权限模型」，优先挂现有系统配置权限。  
- 紫色强调与现有 Element/主题主色冲突时，以站点主色为准，不另造色板。

## 非目标

- 不新增第五种语言；不做翻译内容管理；不改用户已保存个人偏好（除语言被关闭后的回落规则）。
